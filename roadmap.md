### Фаза 2. Миграция на PostgreSQL и промышленный FastAPI бэкенд (Недели 1–4)

#### Цель:
Замена легковесного Express/mock-хранилища на асинхронный бэкенд с отказоустойчивой СУБД.

#### Задачи:
1. **База данных PostgreSQL 15+**:
   - Развертывание PostgreSQL кластера с расширениями `uuid-ossp`, `pgcrypto` и `vector` (pgvector).
   - Накатывание схемы `schema.sql` через Alembic-миграции.
   - Импорт исходного массива данных через `data_migration.sql`.
   - Настройка пула асинхронных соединений `asyncpg` с PGBouncer.
2. **FastAPI ядро API**:
   - Реализация сервисных слоев (Service Layer) и репозиториев (Repository Pattern) на SQLAlchemy 2.0.
   - Аутентификация JWT (Access + Refresh токены) с разграничением ролей (Admin, Director, Accountant, Manager, Dispatcher, Mechanic).
   - Эндпоинты `/api/v1/equipment`, `/api/v1/shifts`, `/api/v1/crm`, `/api/v1/analytics`.
3. **Безопасность и мониторинг**:
   - Настройка CORS, Rate Limiting (SlowAPI), структурированное логирование (Structlog).
   - Docker Compose среда для локальной разработки и CI/CD пайплайн на GitHub Actions.

#### Критерии готовности (DoD):
- 100% покрытие эндпоинтов контрактами Pydantic v2.
- Время ответа аналитических запросов < 120 мс при 100 000 записей смен.
- Успешные интеграционные тесты `pytest-asyncio`.

### Фаза 3. Интеграция телематики (ГЛОНАСС/GPS/ДУТ) и ЭДО (Недели 5–8)

#### Цель:
Автоматический сбор фактических данных об эксплуатации техники без ручного ввода диспетчером.

#### Задачи:
1. **Интеграция с телематическими платформами (Wialon, Omnicomm, АвтоГРАФ, СКАУТ)**:
   - Коннектор по API / Webhook для получения данных зажигания, геозон, моточасов и уровня топлива в баке.
   - Фоновый воркер (Celery / ARQ) сбора телеметрии каждые 5 минут.
   - Автоматическое создание предзаполненного сменного рапорта при возвращении борта на базу или завершении геозоны объекта.
2. **Аудиторская сверка "Факт vs Путевой лист vs Карта водителя"**:
   - Детекция расхождения моточасов (разница более 30 минут).
   - Детекция отклонений расхода топлива (> 10% или > 15 л) с учетом внутрипарковых переливов ГСМ между единицами техники на пример на бульдозер или кран.
   - Учёт и переаресация затрат при переливе(закуп топлива в свой бак для перелива другой техники (режим заправщика)) а так же в случае покупки зап.частей мелкого ремонта для другой техники.   
   - Регламент: при детекции отклонений расхода формируется Alert в `anomaly_alerts`, дата фиксируется в `fuel_audit_logs`, а водителю отправляется уведомление для отчета.
3. **Электронный документооборот (ЭСМ-7 и УПД)**:
   - Интеграция с Контур.Диадок / СБИС по API для отправки подписанных актов заказчикам.
   - Генерация печатных форм ЭСМ-7 и актов оказания услуг в PDF с QR-кодом верификации.

#### Критерии готовности (DoD):
- Погрешность фиксации моточасов снижена до 1%.
- Сквозная фиксация дневных отклонений по ГСМ с уведомлением водителя и закрытием в конце месяца без остановки работы техники.

### Фаза 4. Мультиагентная система ИИ и RAG-база знаний (Недели 9–12)

#### Цель:
Предоставление руководству автономных ИИ-агентов, решающих управленческие и финансовые задачи.

#### Задачи:
1. **RAG-инфраструктура**:
   - Конвейер парсинга внутренних регламентов компании, технологических карт ТО и договоров субаренды.
   - Генерация векторных представлений (Gemini `text-embedding-004`) и сохранение в pgvector с HNSW-индексами.
   - Реализация гибридного поиска (Hybrid Search = Dense Vector + BM25) с ранжированием Cross-Encoder.
2. **Оркестрация на LangGraph**:
   - Внедрение `Master Router` для интеллектуального разбора запросов.
   - Реализация 5 профильных агентов:
     * *Executive Agent* — стратегический сводный отчет, P&L, прогноз чистой прибыли.
     * *Profitability Agent* — глубокий аудит маржи по каждой машине и контрагенту.
     * *Audit Agent* — расследование аномалий, перерасхода ГСМ и приписок часов.
     * *CRM & Receivables Agent* — контроль кредитных лимитов и формирование претензий.
     * *Fleet Maintenance Agent* — предиктивный расчет остатка ресурса и планирование ремзоны.
3. **Безопасный Data Sandbox**:
   - Доступ к БД только в режиме Read-Only с проверкой запросов через AST-парсер.
   - Защита от prompt-инъекций и утечки персональных данных водителей.

#### Критерии готовности (DoD):
- Точность извлечения регламентов RAG (Recall@5 > 92%).
- Формирование сложного аналитического отчета агентом < 4 секунд.

### Фаза 5. Мобильное приложение машиниста и интеграция с 1С (Недели 13–16)

#### Цель:
Оцифровка последнего звена (машинист в кабине) и сквозная синхронизация с бухгалтерской базой 1С.

#### Задачи:
1. **PWA / Telegram-бот водителя (Driver Bot)**:
   - Простой интерфейс для смартфона: старт смены, пауза, фотофиксация счетчика моточасов и чека заправки/ремонта.
   - Учет трат с корпоративной банковской карты предприятия (топливо, ГСМ, запчасти для ремонта) с обязательным полем «Назначение платежа» (для своей машины или перелив/передача на другую технику предприятия, например с самосвала на кран) и автоматическим пробросом уведомлений в CRM/ERP с пересчетом баланса.
   - Оффлайн-режим (IndexedDB) с синхронизацией при появлении связи на удаленном строительном объекте.
   - Фиксация подписи прораба на экране смартфона для оперативного закрытия ЭСМ-7.
2. **Двусторонняя интеграция с 1С:ERP / 1С:Бухгалтерия СХ**:
   - OData / REST API шлюз обмена первичными документами.
   - Выгрузка реестров начислений сдельной ЗП водителей в 1С:ЗУП.
   - Загрузка статусов банковских выписок (оплат от клиентов) для автоматического гашения дебиторки.
3. **Финальное нагрузочное тестирование и масштабирование**:
   - Оптимизация работы с автопарком от 500 единиц техники.
   - Развертывание в Kubernetes (k8s) с автомасштабированием по нагрузке.

## 3. Матрица рисков и стратегия их снижения

| Риск | Вероятность | Влияние | Стратегия снижения |
| :--- | :--- | :--- | :--- |
| **Саботаж машинистами ввода данных в мобильном приложении** | Высокая | Высокая | Привязка сдельной премии водителя к своевременности закрытия смены в приложении; дублирование данных телематикой. |
| **Нестабильная связь на удаленных строительных площадках** | Высокая | Средняя | Архитектура Local-First и PWA с фоновой синхронизацией Service Worker при появлении сети. |
| **Ошибки и галлюцинации LLM в финансовых расчетах** | Средняя | Критическое | Все математические расчеты вынесены в детерминированные Python/SQL инструменты (`Deterministic Tool Calling`), LLM занимается только интерпретацией. |
| **Задержка согласования актов крупными заказчиками** | Средняя | Высокая | Внедрение автоматизированного ЭДО Диадок и предиктивного CRM-агента, формирующего напоминания до наступления просрочки. |

## 4. Стек технологий целевой архитектуры

- **Frontend**: React 19, TypeScript, Tailwind CSS, Lucide Icons, SheetJS (`xlsx`), Motion.
- **Backend**: Python 3.11+, FastAPI, SQLAlchemy 2.0, Pydantic v2, Alembic, Celery / Redis.
- **Database & Storage**: PostgreSQL 15+, pgvector, MinIO / S3 (сканы рапортов и актов).
- **AI & RAG**: Google Gemini 2.5 Pro / Flash, Gemini text-embedding-004, LangGraph, LangChain Core.
- **DevOps**: Docker, Docker Compose, Nginx, GitHub Actions, Prometheus + Grafana.
